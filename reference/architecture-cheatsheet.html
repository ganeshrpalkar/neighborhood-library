Concurrency Pattern (Borrow)

def borrow_book(db, book_id, member_id):
    # 1. Lock row — concurrent borrows queue here
    book = db.scalars(
        select(Book).where(Book.id == book_id).with_for_update()
    ).first()

    # 2. Check while holding the lock
    if book.available_copies < 1:
        raise ConflictError(...)

    # 3. Mutate + commit atomically
    book.available_copies -= 1
    db.add(Loan(...))
    try:
        db.commit()
    except IntegrityError:      # defense-in-depth (layer 2)
        db.rollback()
        raise ConflictError(...)
    # Layer 3: DB CHECK (available_copies >= 0) enforced by PostgreSQL

Session Dependency (Auto-Commit / Auto-Rollback)

def get_session():
    session = SessionLocal()
    try:
        yield session
        session.commit()    # success
    except Exception:
        session.rollback()  # any error
        raise
    finally:
        session.close()     # always

"What Would You Do Differently?"

  • Events table for loan lifecycle — fine history is currently a single overwritten field
  • Roles/permissions table instead of JSON column — better for multi-role or tenant-scoped access
  • APScheduler first, Celery later — Celery is over-engineered for one daily job at this stage
